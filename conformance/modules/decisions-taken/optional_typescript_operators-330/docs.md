# Decision 330 — `?T` is read with TypeScript's operators and has no methods; `result` goes; a type declared in a type is its associated type.

The example matches URLs against a two-route table and reads every optional answer with an operator. `matchPath` answers a `?RouteMatch`: `post?.entry.pattern ?? "none"` reads the matched pattern, `/blog/[slug]`, and `post?.params.at("slug") ?? ""` reads the bound segment, `hello`. `params.at` itself answers a `?string`, and through `?.` the whole chain is a `?string`, not a `??string`, because `?.` flattens. `/about` matches nothing, so `missing?.params.at("slug") ?? "no slug"` gives the default. `matchPath(table, "/docs/a/b")?.rest?.[1]` indexes the optional catch-all remainder and answers `b`. `notFound(true)?.("/about")` calls an optional function value, and with `notFound(false)` the function is `null`, so the default `silent` is printed. `post!.entry.kind` takes the match when the program knows it is there; a `null` at that point would stop the program with the location and the expression, the same on every target.

`Link` is declared in the body of `Site`, so it is `Site`'s associated type, written `Site.Link` in the signature of `Site.links` and in its constructor. `links.at(1)?.label ?? "unlabelled"` reads a member that is itself a `?string`. `parsePattern` answers a `Result`, and the program reads it with that type's own methods: `parsed.isOk()` and `parsed.map({ segs -> segs.length }).unwrapOr(0)`, which answers `2`; there is no `result` namespace to call instead, and `unwrapOr` is never written on a `?T`. The parentheses in `(missing?.entry.pattern ?? "") == "" || links.length > 2` are required: `??` next to `||` with no parentheses is a compile error. Writing `?.` on a value that is never `null`, as `links?.[1]` with `links` an `Array`, is a compile error too.

Cells in this repository that prove it: none yet. The library's code already reads its optionals with `??` (`f.at(0) ?? ""` in `src/table.bp`); its feature cells come with front 157's Conformance step (decision 465), after 144 B-20's codemod commit over the library.
